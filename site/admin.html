Bygga och admin

För den som bygger ISO-filerna och skriver stickor.

Vad som finns var

build/
  artifacts.lock        låsta artefakter: namn, URL, SHA256
  maps.lock             kartfiler som Minimal hämtar vid första start
  sources.conf          var varje artefakt kommer ifrån
  build.sh              fetch, verifiera, bygg Oden, staging, live-build -> ISO + SBOM
  fetch.sh              hämtar och verifierar artefakter
  scripts/bump.sh       uppgradera en artefakt i lås-filen
  scripts/build-oden.sh bygger Oden för Linux från källa (docker, PyInstaller)
  scripts/stage.sh      packar upp artefakter i bilden under /opt
  scripts/make-stick.sh skriver bilden till en USB-sticka
  config/ overlay/      live-build-konfig och filer som kopieras in i bilden
  tests/run.sh          offline-tester av skripten

Cache och byggresultat (build/cache/, build/out/) ligger utanför git.

Krav på byggmaskinen

Linux med docker, GitHub CLI (gh, inloggad), python3, curl, tar, zstd, gdisk, fdisk, e2fsprogs och parted. Byggmaskinen behöver nät. Bara den färdiga stickan ska gå att köra offline.

Bygga

./build/tests/run.sh      # snabb kontroll av skripten (offline)
./build/build.sh          # -> build/out/oden.iso + SBOM.txt

# ISO-varianter för Etcher:
ODEN_VARIANTS=minimal,karta,karta-ai ./build/build.sh
# -> build/out/oden-<variant>-<version>.iso + .sha256
  • karta och karta-ai kräver ODEN_ASSETS med maps/ (och ollama/ för AI). minimal kräver ifylld build/maps.lock.
  • build.sh --no-fetch hoppar bara över fetch.sh. Bygget behöver ändå nät.
  • Spara build/out/SBOM.txt tillsammans med versionsstämpeln /etc/oden-release i bilden.

Publicera

Ladda upp ISO-filerna och skapa sedan listan som sidan Ladda ner visar:

build/scripts/release-json.sh https://<bas-url> > site/releases.json
git add site/releases.json && git commit && git push

Pages publicerar om sajten vid push till main som rör site/.

Skriva sticka direkt

sudo ./build/scripts/make-stick.sh [--with-ai] build/out/oden.iso /dev/sdX

Kräver en flyttbar hel disk på minst 60 GB och frågar innan allt raderas. Layout: p1 ISO-data, p2 EFI, p3 oden-assets (ext4, skrivskyddad), p4 persistence (krypteras vid första start). För vanligt bruk räcker Etcher med en variant-ISO.

Uppgradera ett verktyg

Alla versioner står i artifacts.lock. Uppgradering är alltid bumpa, granska, bygg om:

./build/scripts/bump.sh --list
./build/scripts/bump.sh go-pmtiles 1.32.0
git diff build/artifacts.lock
./build/tests/run.sh && ./build/build.sh
ArtefaktAtt kontrollera efter uppgradering
oden-sourceOden byggs om automatiskt. Kontrollera att Oden startar och läs upstreams CHANGELOG.
oden-valvValv och plugin ska vara kompatibla med Obsidian-versionen. Map View ska peka på 127.0.0.1:8081.
signal-cli, jre-x64Bundlas in i Oden-binären, som byggs om. Matcha Java-versionen mot vad Oden kräver.
obsidian-appimageObsidian ska starta med valvet och Map View.
go-pmtilesKontrollera flaggorna för serve (se pmtiles.service).
ollamaKontrollera att modellerna i ollama/ fortfarande laddas. Arkivet är ca 1,5 GB.
  • Debian-paket hämtas av live-build vid varje bygge. De är medvetet inte pinnade. SBOM.txt visar vilka versioner som ingick i just den ISO:n.
  • Ny artefakt: lägg en rad i sources.conf och en i artifacts.lock (<namn> PENDING_URL PENDING), kör bump.sh <namn> latest, lägg uppackning i stage.sh och ett testfall i tests/run.sh.
  • "N asset matchar": upstream har bytt filnamn. Justera regexet i sources.conf.

Om Oden för Linux

Upstream släpper bara Windows och macOS. build-oden.sh bygger Linux-binären från git-taggen med upstreams egen s7_watcher.spec (JRE och signal-cli inbyggda) i python:3.12-bookworm. Resultatet är build/cache/oden-linux, ca 200 MB. Radera filen för att bygga om.

Kartor

Rastret sverige-raster.pmtiles (zoom 0–14, ca 2,25 GB) renderas en gång från vektorkartan med build/scripts/map/render-map.sh. Se KARTRENDERING.md. Högsta zoomnivån står i build/map.conf (MAP_MAXZOOM). Fel värde ger tomma eller suddiga rutor.

Kända begränsningar

  • Oden-binären är inte bit-för-bit reproducerbar, eftersom Python-beroendena är angivna som >=. pip freeze och SBOM dokumenterar vad som ingick.
  • Oden är en "onefile"-binär som packar upp sig själv (ca 200 MB) i /tmp (RAM) vid varje start.
  • Oden visar versionen v0.0.0-dev, eftersom bygget inte skickar in något versionsnummer.
  • Obsidian körs som extraherad AppImage och kan kräva --no-sandbox.
  • Ollama-modeller har inget versionslås.

Nycklar och förlorad stick

Varje stick får egen LUKS-nyckel vid första start. Det finns ingen central nyckel och ingen header-backup, så förlorad lösenfras betyder förlorad data. Vid förlorad stick: koppla bort stickans enhet i Signal och spärra dess TAK-certifikat.

Den fullständiga guiden finns i ADMINGUIDE.md.
